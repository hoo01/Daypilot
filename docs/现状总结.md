## Coordinator 内部逻辑（关键规则）

```
before_agent_callback（并行）：
  track_goals → get_relationship_context → analyze_health
  ↓ 注入 INSTRUCTION 模板（含 Upcoming events / Today's Google Calendar events）
Coordinator (Gemini 2.5 Flash)
  MODE A：直接回答（不调工具，context 已足够）
  MODE B：调用 plan_schedule（用户明确要求排班）
           规则：
           - 命名任务（"I want to finish assignment7"）
             → 识别为 calendar_event + 时间段转换
               ("this morning"→08:00-12:00, "tonight"→19:00-22:00 等)
           - <user_context> 里 "Today's Google Calendar events"（来自
             calendar_cache 的真实日历事件）必须原样作为 calendar_event 传入
           - 用户确认某个策略后 → 调 confirm_schedule 持久化选择
  adjust_schedule：先 get_today_schedule 取已确认排程作为 current_schedule，
                   没有的话退回 plan_schedule 生成新计划
```

## 已知问题

### 1. 回复延迟 (~20-30s)
- 演示前需先发一遍"热身"请求
- 前端 AgentDrawer 有分步加载提示（"Checking your goals…" → "Analyzing your energy…"），填充等待感
- Gemini thinking 模式未关闭（冒险，暂不动）

### 2. 对话模型倾向
- 对 "What should I focus on today?" 这类开放性问题，模型**不会**只回轻量 insight，会顺手生成完整 schedule（含多策略）
- 内容质量高，demo 时正面利用（"什么都想到了"比"只说四句"更有冲击力）
